# 재무 대시보드 화면 기획 명세 (Finance Dashboard Spec)

> **문서 버전**: v2.1 (시뮬레이션 기준 전면 갱신 — index.html 반영)
> **최종 갱신일**: 2026-04-09
> **기획 방향**: 통계/분석이 아닌 **행동 지향적(Action-Oriented)** 실무 운영 뷰. 역할을 명확히 나누어(재무담당자 vs 대표) 오늘 당장 처리해야 할 시급도 높은 항목을 시각적 위계의 최상단에 배치한다.

---

## 1. 업무 목적

- 시스템 접속 시 어떠한 메뉴 탐색 없이 곧바로 **본인 역할(Role)**에 할당된 병목 지점(결재 대기, 이체 임박, 불일치 발생)을 확인하고 **즉시 해소(Call-to-Action)**할 수 있도록 돕는다.
- 단순 리스트 나열을 지양하고 긴급도 기반의 업무 큐(Task Queue) 구조를 채택한다.

---

## 2. 사이드바 네비게이션 구조 *(v2.1 갱신)*

사이드바는 **7개 메뉴**로 구성되며, 좌측의 접기/펼치기 토글로 최소 너비(64px) 및 확장 너비(220px) 전환이 가능하다.

| 순서 | Menu ID | 메뉴명 | 연결 화면 |
|---|---|---|---|
| 1 | `dashboard` | 대시보드 | index.html (메인 랜딩) |
| 2 | `ap` | 지급요청관리 | index.html |
| 3 | `periodic` | └─ 정기결제 관리 (서브 탭) | index.html |
| 4 | `payments` | 지급 내역 관리 | index.html |
| 5 | `unpaid` | 미지급 관리 | index.html |
| 6 | `recon` | 세금계산서 대사 | recon.html |
| 7 | `adj` | 정산 조정 관리 | recon.html |

**정기결제 관리 (periodic) 동적 서브 메뉴 규칙 *(v2.1 신규)***:
- `지급요청관리(ap)` 메뉴 클릭 시에만 `정기결제 관리(periodic)` 탭이 사이드바에 표출 (`isPeriodicSubMenuVisible = true`)
- 다른 메인 메뉴(대시보드, 지급 내역, 미지급 관리 등) 클릭 시 자동으로 숨김 (`isPeriodicSubMenuVisible = false`)
- reactive `navMenus` 배열에서 `isSub: true`인 항목을 조건부 렌더링으로 처리

## 3. 대시보드 아키텍처 (2-Zone System)

대시보드는 효율적인 업무 흐름 관리를 위해 2개의 구역(Zone)으로 나뉜다.

### Zone B: Actionable Metrics (핵심 지표 카드)
- 업무 상태별 볼륨을 보여주는 **5개 카드** 영역.
- **레이아웃**: 좌측 상단에 제목, **우측 하단**에 해당 지표의 숫자(Count)를 **대형 폰트** 및 전용 단위(건/원)와 함께 배치.
- 카드 클릭 시 해당 메뉴로 즉시 이동 (필터 상태 전달).

| 카드 | 지표 | 클릭 시 이동 |
|---|---|---|
| 1 | **지급처리 대기** (APPROVED 상태 건수) | AP 메뉴 |
| 2 | **미지급 건수** (전체 미결제 건수) | 미지급 관리 메뉴 |
| 3 | **미지급 금액** (확정된 모든 부채 합계 금액) | 미지급 관리 메뉴 |
| 4 | **미대사 건수** (불일치/부분일치 세금계산서 합계) | 세금계산서 대사 (recon.html) |
| 5 | **정산조정 대기** (승인 완료 후 처리 대기 중인 건) | 정산 조정 관리 (recon.html) |

> ※ **참고**: 카드/현금 결제 증빙은 구매담당자가 ERP 내에서 직접 첨부하며, 재무담당자는 지급내역 화면에서 Read-Only로 확인합니다. 대시보드에 별도 카드 증빙 KPI는 운영하지 않습니다.

### Zone C: High-Density 3-Column 큐 뷰 (3-Panel Grid)
- **C-1 (Left): 지급요청 실행 큐 (AP Queue)**
  - 결재 승인된 payables 목록 (거래처 / 금액 컬럼)
  - 상단에 [전체보기 →] 버튼 → AP 메뉴 이동
- **C-2 (Center): 미대사 계산서 (Recon Queue)**
  - 미매칭 세금계산서 목록 (공급사 / 금액 컬럼)
  - 상단에 [대사하러 가기] 버튼 → recon.html로 이동
- **C-3 (Right): 미지급 위험 모니터링 (Unpaid Risk)**
  - 거래처별 누적 미지급 카드 (업체명 / 미결 N건 / 누락 잔액 금액)
  - 2천만원 초과 상위 2개 업체 rose 색상 강조
  - 상단에 [상세보기] 버튼 → 미지급 관리 메뉴 이동

## 4. 역할별 뷰 명세 — A. 재무담당자 뷰 (Finance Exec)

**목적**: 대사 불일치를 빠르게 해결하고, 대표 승인이 떨어진 건들에 대해 **오차 없이 지급(이체)을 실행**하는 실무 전진기지.

재무담당자 로그인 시 대시보드는 **Zone B (5종 지표) + Zone C (3-Column 큐)** 구조로만 표시된다.  
헤더 결재 드로어, AP 리스트 인라인 [승인]/[반려] 버튼은 **표시되지 않음**.

---

## 5. 대표 로그인 전용 글로벌 컴포넌트 (결재 드로어)

재무담당자와 대표는 **동일한 대시보드 및 업무 화면**을 공유한다.  
대표 로그인 시(`isCEO === true`)에만 다음 두 가지 UI 요소가 추가로 표출된다.

### 5.1 헤더 결재 알림 드로어 (🔔 아이콘)

- **위치**: 전역 헤더 우측 사용자 정보 왼쪽에 고정 배치 (대표 로그인 시에만 노출)
- **뱃지**: CREATED 상태 payables + 정산조정 승인대기 건수 합산 표시 (indigo 뱃지)
- **동작**: 클릭 시 슬라이드 드로어 열림 / 다시 클릭 시 닫힘

#### 드로어 내부 구성

| 섹션 | 내용 |
|---|---|
| **⏳ AP 결재 대기 (payables)** | CREATED 상태 payables 목록. 거래처명 / 금액 / 기한 표시. 각 행에 [승인] [반려] 인라인 버튼 |
| **🔄 정산조정 결재 대기** | '대기' 또는 '진행중' 상태 정산조정 건 목록. 조정 유형 / 금액 / 원거래ID 표시. 각 행에 [승인] [반려] 버튼 |
| **빈 상태** | "결재 대기 건이 없습니다" 안내 메시지 |

### 5.2 AP 리스트 인라인 결재 버튼

- **위치**: 지급요청관리(AP) 리스트 내 각 행 우측 (`결재` 컬럼, `v-if="isCEO"`)
- **노출 조건**: `pbl_payable_status === 'CREATED'`인 행에만 [승인] [반려] 버튼 표출
  - `[승인]` (indigo) → 해당 payable의 status를 APPROVED로 전환
  - `[반려]` (rose) → 해당 payable의 status를 REJECTED로 전환
- 재무담당자 로그인 시에는 해당 컬럼 자체가 숨겨짐 (`v-if="isCEO"`)

### 5.3 정산조정 리스트 인라인 결재 버튼

- **위치**: 정산조정 관리(adj) 리스트 내 각 행 우측 (대표 로그인 시에만 노출)
- **노출 조건**: `adj.status === '대기' || '진행중'`인 행에만 [승인] [반려] 버튼
- [승인] → 상태 '승인완료' / [반려] → 상태 '반려'

### 5.4 역할 전환 Demo 버튼

헤더 우측에 `[👤 재무담당 ↔ 🔴 대표 모드]` 토글 버튼 배치 (프로토타입 시뮬레이션 전용).  
실제 개발에서는 로그인 세션의 `role` 값으로 대체.

## 6. 컴포넌트 정책 및 UI/UX 표준 가이드

### 6.1 버튼 및 액션 (Call to Action)
- 단순 [전체보기] 링크보다, `[즉시 지급 실행 (5건)]`과 같은 행위를 유도하는 마이크로카피 사용.
- 기한 초과(Overdue), 오늘 기한(Due Today) 항목은 Red/Rose 색상 태그로 강한 텐션 유발.

### 6.2 필터 상태 유지 (Retention)
- 대시보드 카드 클릭 → 상세 리스트로 이동 시, 클릭한 상태 값(예: APPROVED)이 해당 리스트의 기본 필터로 세팅.

### 6.3 로딩 전략 (UX)
- 빠른 초기 반응을 위해 Skeleton UI 먼저 표시 후, 각 카드/위젯 비동기 조회.
- 현재 시뮬레이션에서는 localStorage 기반 동기 로드.

### 6.4 CSS/디자인 표준
- 주요 색상 팔레트: slate / blue / indigo / rose / emerald / amber
- 폰트: Inter (Google Fonts)
- 카드 스타일: `glass-panel` (배경 rgba(255,255,255,0.95) + backdrop-filter)
- 테이블: `.erp-table` (sticky thead, 별도 border-spacing)
- 전환 애니메이션: `animate-[fadeIn_0.3s_ease-out]`

## 7. 경계 및 향후 고도화

- 복잡한 자금계획 시뮬레이션이나 다차원 분석 BI 차트는 이번 1차 실무 대시보드 범위에 **미포함**. (Phase 2 확장)
- 모든 지표 클릭 시 원장 기반의 정확한 리스트로 **오류 없이** 연결되는 정합성 보장이 최우선 기술 요건.
- **Phase 2**: localStorage → RESTful API 전환, 실시간 데이터 동기화, 세션 기반 역할(Role) 관리, 감사 로그 고도화.
