# 정산조정관리 화면 기획 명세 (Settlement Adjustment Spec)

> **문서 버전**: v2.0 (시뮬레이션 기준 전면 갱신 — recon.html 반영)
> **참조**: recon.html (정산 조정 관리 섹션), index.html (정산조정 모달)
> **최종 갱신일**: 2026-04-09

---

## 1. 업무 목적

원거래(발주서/지급요청/지급내역/대사건) 이후 발생한 **환수, 반환지급, 추가지급, 추가수금 등 후속 조정거래를 독립적으로 관리**한다.

**포함 업무 (현행 기준)**
1. 정산조정 관리 리스트
2. 정산조정 상세 패널 (Split-View 우측)
3. 연결 및 승인 처리 액션 패널 (하단)

**정산조정 원칙**
- 지급관리(②), 대사관리(⑤)와 연결될 수 있으나, **실제 행위는 정산조정관리에서만 수행**
- 독립 메뉴(recon.html?menu=adj)로 운영되며, index.html 지급내역 상세 및 recon.html 대사 화면에서 **모달 팝업**을 통해 크로스모듈 발의 가능
- 발의된 데이터는 **localStorage** 동기화를 통해 정산조정 리스트에 실시간 반영
- 후속거래는 반드시 **원거래 연결 및 추적이 가능**해야 함

---

## 2. 정산조정 유형

| 유형 코드 | 의미 | 방향 |
|---|---|---|
| `환수` | 과다지급 후 반환 청구 | 입금 방향 |
| `반환지급` | 취소/반품 후 공급사에 환불 | 지급 방향 |
| `추가지급` | 추가 용역, 단가 조정 등 | 지급 방향 |
| `추가수금` | 추가 납품, 정산 오류 보정 | 입금 방향 |
| `기타조정` | 분류 불가능한 조정 | — |

> **지급 방향**: 반환지급 / 추가지급 → payments 연결  
> **입금 방향**: 환수 / 추가수금 → 정산조정 내부에서 입금 추적

## 3. 화면 구조 (메뉴 트리)

```
정산조정관리 (recon.html?menu=adj)
  ├── 리스트 (좌측 패널, 7:5 Split-View)
  └── 상세 패널 (우측)
        ├── 원거래 추적 섹션 (Origin 클릭 → 해당 원거래 화면 추적 이동)
        ├── 상세 조정 사유 이력
        ├── 후속거래 연결 섹션 (지급 방향 / 입금 방향 분기)
        └── 연결 및 승인 액션 패널 (하단)

[크로스모듈 발의 진입점]
  ├── index.html > 지급내역 상세 > [+ 정산조정(환수 등) 발의] 버튼 → 모달
  └── recon.html > 대사 화면 > ERP 카드 [정산조정 발의] 버튼 → 모달
```

## 4. 정산조정 리스트

### 4.1 조회 필터

| 필터 | 유형 | 옵션 |
|---|---|---|
| 원거래 번호/사유 | 텍스트 검색 | — |
| 조정 유형 | 드롭다운 | 전체 / 환수 / 반환지급 / 추가지급 / 추가수금 / 기타조정 |
| 조정 상태 | 드롭다운 | 전체 / 대기 / 진행중 / 승인완료 / 반려 |
| 거래처별 그룹보기 | 토글 | Accordion 형태 |

### 4.2 리스트 컬럼

| 컬럼 | 데이터 소스 | 비고 |
|---|---|---|
| 결제일 | `adj.pay_date` | |
| 결제수단 | `adj.method` | 계좌이체 / 법인카드 / 현금 배지 |
| 수취인(가맹점) | `adj.vendor` | |
| 조정유형 | `adj.type` | indigo 배지 |
| 조정사유 | `adj.reason` | 최대 길이 truncate |
| 조정금액 | `adj.amount` | 환수/반환지급 → 빨간색 (마이너스 표시) |
| 현재상태 | `adj.status` | 대기(amber) / 진행중(blue) / 승인완료(emerald) / 반려(rose) |
| 결재 (대표 전용) | — | 대기/진행중 행에만 [승인] [반려] 인라인 버튼 표출 |

## 5. 정산조정 상세 패널

### 5.1 기본 정보

| 항목 | 설명 |
|---|---|
| 원래의 모거래(Origin) | 클릭 시 원거래 화면(`?menu=ap&search=[ID]`)으로 추적 이동 — **Deep Link** |
| 조정 발생 유형 | 유형 코드 (indigo 텍스트) |
| 발생일자 | 조정 생성일 |
| 조정(가감) 금액 | 빨간색 강조 (환수/반환지급은 마이너스 표시) |
| 현재 상태 | 상태 배지 |

### 5.2 상세 조정 사유 이력
- `adj.reason` 텍스트를 인용문 형태로 표시
- "어떤 거래 대비 차액을 발생시키는가" 맥락 포함

### 5.3 후속거래 연결 섹션

**지급 방향 (반환지급 / 추가지급):**
- 연결된 payment가 있으면 → emerald 배경으로 pay_sn / 거래처 / 날짜·금액·수단 표시 + [연결 해제] 버튼
- 미연결이면 → [지급내역 연결하기] 버튼 (지급 피커 열기)

**입금 방향 (환수 / 추가수금):**
- 정산조정관리 내부에서 추적 (별도 receipts 연결 아님)
- teal 배경 박스에 입금 예정액 + 처리 상태 표시

## 6. 정산조정 처리

### 6.1 생성 흐름 (모달 발의)

```
[원거래 화면에서 모달 발의]
  │
  ▼
─ origin: 원거래 ID (자동 채워짐, Read-Only)
─ type: 조정 유형 선택 (환수 / 반환지급 / 추가지급 / 추가수금 / 기타조정)
─ amount: 조정 금액 입력
─ reason: 조정 사유 입력 (textarea)
  │
  ▼
[조정 생성 발의] 클릭
  │
  ▼
localStorage에 정산조정 데이터 추가
  │
  ▼
정산조정 리스트(recon.html?menu=adj)에 즉시 반영 (상태: 대기)
```

### 6.2 상태 전이

```
대기 ──► 진행중 ──► 승인완료 (대표 승인)
  │          │
  ▼          ▼
 (직접)    반려 (대표 반려)
```

| 상태 | 의미 | 액션 주체 |
|---|---|---|
| 대기 | 조정 생성됨, 결재 요청 전 | 기안자 / 재무담당자 |
| 진행중 | 대표 결재 요청 완료 | 재무담당자 (결재요청 버튼) |
| 승인완료 | **대표 승인 완료 확정** | 대표 (승인 버튼) |
| 반려 | 기안 무효 또는 대표 반려 | 대표 (반려 버튼) |

### 6.3 액션 패널 (하단 고정) — [NEW]

재무담당자가 조정 결과를 최종적으로 시스템에 반영하기 위한 수기 처리 패널입니다.

| 항목 | 내용 |
|---|---|
| **실제 입/출금 일자** | 조정액이 실제 통장에 반영된(또는 될) 날짜 선택 (`procData.date`) |
| **입출금 적요** | 통장 적요에 기록될 메모 (`procData.note`) |
| **처리 금액** | 실제 처리된 금액. 조정액과 다를 경우 차액이 잔액으로 남음 (`procData.amount`) |
| **[입금/출금 내역으로 추가 후 완료]** | 클릭 시 `payments` 또는 `receipts` 형태의 기록이 생성되며 조정 상태가 '승인완료'로 전환됨 |

### 6.4 대표 전용 액션 (결재)

대표 로그인 (`isCEO === true`) 시에만 노출되는 결재 관련 액션입니다.

- **리스트 인라인 버튼**: 대기 / 진행중 상태 행 우측에 [승인] [반려] 버튼 표출.
- **드로어 결재**: 헤더 결재 드로어에서 즉시 처리 가능.

### 6.5 원거래 추적 점프 (Deep Link)

상세 패널의 Origin 클릭 시:
- `origin.startsWith('PAY_')` → `index.html?menu=payments&search=[payId]`로 이동
- 기타 원거래 → `index.html?menu=ap&search=[originId]`로 이동

## 7. 크로스 모듈 발의 진입점

| 발의 위치 | 연결 방식 |
|---|---|
| 지급내역 상세 (index.html > payments) | [+ 정산조정(환수 등) 발의] 버튼 → 모달, origin = `pay_sn` 자동 매핑 |
| 대사 화면 ERP 카드 (recon.html > recon) | [정산조정 발의] 버튼 → 모달, origin = `TI_[id]` 자동 매핑 |

## 8. 경계 및 연결 원칙

| 원칙 | 내용 |
|---|---|
| **행위 주체** | 조정 행위는 오직 정산조정관리에서만 수행 |
| **연결 추적** | 후속거래 → 원거래 연결 필수 (origin ID 기록) |
| **판단과 행위 분리** | 대사관리에서 불일치 판단 → 정산조정에서 실제 처리 |
| **지급 방향** | 지급 방향 후속거래는 payments와 연결 |
| **입금 방향** | 현재 범위에서 정산조정관리 내부에서 추적 |
| **철회 가능** | '진행중' 상태에서 재무담당자가 요청 철회 가능 (대기로 복원) |

## 9. 관련 엔티티 요약

| 엔티티 | 역할 |
|---|---|
| `settlement_adjustments` | 정산조정 헤더 (현재 localStorage 기반 시뮬레이션) |
| `settlement_adjustment_links` | 원거래 연결 (polymorphic) |
| `settlement_adjustment_payments` | 후속 지급 연결 |

> 현재 시뮬레이션은 **localStorage** 방식으로 구현되어 있으며, 백엔드 DB 연동 시 별도 API 설계 필요.
