# 지급관리 화면 기획 명세 (AP / Accounts Payable Spec)

> **문서 버전**: v2.0 (시뮬레이션 기준 전면 갱신 — index.html 반영)
> **참조**: index.html (지급요청관리, 정기결제관리 섹션), erp_finance_schema.sql
> **최종 갱신일**: 2026-04-09

---

## 1. 업무 목적

매입·발주·거래명세서 기반으로 지급 요청을 받고, **승인·집행까지** 관리한다.

**포함 업무 (현행 기준)**
1. 지급요청 리스트 조회 (AP 메뉴)
2. 지급요청 상세 패널 (Split-View 우측)
3. 지급처리 (단건 / 일괄)
4. **정기결제 관리** (AP 하위 탭, 별도 Split-View)
5. 거래처 미지급 관리 리스트
6. 미지급 상세 패널 (Split-View)
7. 지급내역 리스트
8. 지급내역 상세 패널

**운영 원칙**
- **불변식**: Invoice는 거래처가 보내온 외부 문서 컨테이너이다. 실제 업무(결재/지급실행) 단위는 `payable`(지급 단위)이다.
- **시나리오 A (카드/현금 선결제 건 유입)**: 구매담당자가 법인카드 또는 현금으로 선결제한 건은 payables 결재/승인 큐를 통과하지 않고 **즉시 payments 레코드(PAID)**로 생성된다. 재무담당자는 지급내역 화면에서 Read-Only로 확인한다.
- **시나리오 B (PO기반 계좌이체)**: PO → cost → **payables 생성(대표 승인결재 필수)** → payment(이체증빙 수집)로 처리.
- **정기결제 자동 분류**: `periodic_vendors` 목록에 등록된 거래처의 **APPROVED 상태** payables는 일반 AP 리스트에서 제외되어 정기결제 관리 탭에만 표출된다.

## 2. 화면 구조 (메뉴 트리)

```
지급 관리 시스템 (Payables & Payments)

  │     ├── 리스트 (좌측 패널)
  │     └── 상세 패널 (우측) + 지급 실행 블록 (하단)

        └── 상세 패널 (우측)
```

## 3. 지급요청 리스트 (payables 목록)

### 3.1 화면 목적
**지급 대기 중인 payables를 조회**하여 처리 우선순위를 파악하고 상세로 진입한다.  
정기결제 등록 거래처의 APPROVED 건은 자동 제외되어 별도 탭에서 관리된다.

### 3.2 조회 필터

| 필터 | 유형 | 옵션 |
|---|---|---|
| 상태 | 드롭다운 | CREATED / APPROVED / 전체 (PAID는 지급내역 탭으로 이동) |
| 거래처 / 청구서 | 텍스트 검색 | 거래처명 + 청구서 번호 통합 검색 |
| 요청일 | 기간 선택 | 시작일 ~ 종료일 |
| 정렬 | 드롭다운 | 최신순 / 기한순 / 금액순 |

> **필터 노출 정책**: `PAID` 상태 건은 '지급내역 관리' 탭으로 이동. AP 리스트에는 `CREATED`, `APPROVED` 상태만 노출.

### 3.3 리스트 컬럼

| 컬럼 | 데이터 소스 | 비고 |
|---|---|---|
| 요청일 | `payables.pbl_requested_at` | |
| 담당자 | `payables.manager` | |
| 거래처명 | `parties.pt_name` via `payables.pt_name` | |
| 납품처 | `payables.delivery_place` | |
| 계약업체 | `payables.contractor` | |
| 납기일 | `payables.delivery_date` | |
| 요청금액 | `payables.pbl_total_amount` | 통화 포함 |
| 상태 | `payables.pbl_payable_status` | 배지 형태 |
| 결재 (대표 전용) | — | CREATED 행에만 [승인] [반려] 인라인 버튼 표출 |

### 3.4 UI 액션
- **[거래처별 그룹보기]** 토글: Accordion 형태로 거래처별 묶음 조회.
- **체크박스 다건 선택 → 일괄 지급 실행**: 하단 블록에 선택 건수·합계 표시 후 일괄 payment 생성.
- **단건 선택**: 우측 상세 패널에 정보 표출 + 하단 블록에서 단건 지급 실행.
- **[승인] / [반려] 인라인 버튼 (대표 전용)**: `isCEO === true`일 때 CREATED 행에만 표출.

## 4. 지급요청 상세 패널

### 4.1 화면 목적
개별 payable의 **청구 내용 확인, 상계(Offset) 처리, 계좌 확인, 지급 실행**을 처리한다.

### 4.2 패널 헤더 정보

| 항목 | 데이터 |
|---|---|
| 거래처명 | `payables.pt_name` |
| 담당자 | `payables.manager` |
| 납품처 | `payables.delivery_place` |
| 계약업체 | `payables.contractor` |
| 납기일 | `payables.delivery_date` |
| 요청일 / 지급 만기일 | `payables.pbl_due_at` |
| 지급 잔액 | `payables.pbl_total_amount` (빨간색 표시) |

### 4.3 대표 피드백 (CEO Comment Box) — [NEW]
- **노출 조건**: `payables.ceo_comment`가 존재할 때 상세 패널 최상단에 노출.
- **디자인 정책**:
  - **APPROVED(승인)**: 초록색(emerald) 배경 및 테두리. "대표 피드백 (전달됨)" 헤더.
  - **REJECTED(반려)**: 빨간색(rose) 배경 및 테두리. "대표 피드백 (반려됨)" 헤더.
- **데이터**: `pbl_payable_status`와 연동되어 담당자에게 반려 사유나 결제 지시 사항을 시각적으로 강조.

### 4.4 실행용 지급 정보 상세 — [NEW]
- **위치**: 상계(Offset) 처리 섹션 상단 또는 하단에 배치.
- **항목**:
  - **지급 수단**: 계좌이체 / 카드 등 (`pbl_proof_details.method`)
  - **은행/예금주**: `pbl_proof_details.account.bank` / `holder`
  - **계좌번호**: `pbl_proof_details.account.number` (복사 가능하도록 강조)
- **목적**: 재무담당자가 인터넷 뱅킹 실행 시 필요한 정보를 화면 이동 없이 즉시 확인.

### 4.5 상계(Offset) 처리 — Cost Allocation 섹션 *(v2.1 갱신)*

**상계 처리 내역 불러오기 버튼 (항상 표출)**
- 표출 조건: `pbl_payable_status === 'CREATED' || 'APPROVED'`일 때 항상 버튼 표출
- 동작: 클릭 시 해당 거래처(`pt_name`)의 `costs.amount < 0`이고 `payable_cost_allocations`에 미할당된 항목을 모달로 불러와 선택·적용

**Cost Allocation 내역 표 (지급 구성 내역)**
- 할당된 비용 항목 목록 (`cost_items`: description, amount, ct_sn)
- `isOffset === true`인 항목(마이너스 비용): 금액 옆에 빨간 `[×]` 버튼 표출
  - `[×]` 클릭 → 해당 offset cost 항목을 할당에서 제거, `pbl_total_amount` 즉시 복원

**원거래 추적 섹션**
- 비용 발생 출처(Origin) Tags: `[PO] PO-2026-XXX` 형태의 클릭 가능한 배지 → PO 상세 모달 팝업 (Read-Only)

### 4.6 지급 실행 블록 (하단 고정)

별도 섹션으로 항상 하단에 고정 표시:

| 상황 | 표시 내용 |
|---|---|
| 체크박스 다건 선택 | 선택 건수 + 합계 금액 + [선택 N건 일괄 지급 실행] 버튼 |
| 단건 선택 (CREATED) | "대표 승인(APPROVED)이 필요합니다" 안내 |
| 단건 선택 (APPROVED) | "단건 결제 모드" 안내 + [선택 1건 즉시 지급 실행] 버튼 |
| 선택 없음 | "항목을 선택(클릭/체크)해 주세요" 안내 |

## 5. 정기결제 관리 (Periodic Payment Management) *(v2.0 신규)*

### 5.1 화면 목적
월 단위 정기성 거래처(대한통운, 마이넌 배관시스템 등)의 **지급요청을 일괄 집계·상계처리·실행**하는 마감 터미널이다.

### 5.2 접근 방식
- 사이드바의 **'정기결제 관리'** 서브 탭 클릭 (지급요청관리 메뉴 선택 시에만 표출되는 동적 서브 메뉴).
- 자동 격리 로직: `periodic_vendors.includes(pt_name) && pbl_payable_status === 'APPROVED'`인 건은 일반 AP 리스트에서 자동 제외됨.

### 5.3 UI 구조 (Split-View)

**좌측 패널 (30%) — 정기결제 업체 관리**
- 신규 업체명 입력 → `[등록]` 버튼으로 등록 / 마우스 호버 시 `[×]` 버튼으로 삭제
- 업체별 카드: 업체명 / PENDING COUNT(대기 건수) / 합계 금액 표시
- 클릭 시 우측 패널에 해당 업체 상세 표출

**우측 패널 (70%) — 결제 명세 및 실행**
- **상단 요약 헤더**: 승인 완료 총액(Gross) / 자동 상계 차감액(Offset) / 최종 이체 예정액(Net) — 3-Column Board
- **지급요청 리스트 테이블**: 지급요청관리(AP)와 동일한 컬럼 구조(요청일/담당자/거래처명/납품처/계약업체/납기일/청구액/상태)
  - 해당 거래처의 `APPROVED` 상태 건만 표출
  - 대기 건이 없으면 "현재 승인 완료된 대기 건이 없습니다" 안내
- **하단 집계 및 상계 섹션** (테이블 아래):
  - **총 이체 필요 금액(Total Transfer Sum)**: net 값 표시 (상계 적용 시 원래 금액 취소선 표시)
  - **상계 처리 내역 불러오기 버튼** (지급요청관리와 동일한 디자인): 항상 표출. 클릭 시 해당 거래처 마이너스 Cost 목록 표출
  - **상계 처리 내역 (OFFSET RECORDS)**: 불러온 마이너스 Cost 항목 목록. 항목 우측에 `[×]` 버튼으로 개별 제거 가능
  - **지급 실행 블록** (지급요청관리와 동일한 디자인): 하단에 배치
    - "[선택된 업체 일괄(최종 N원) 즉시 지급 실행]" 버튼

### 5.4 상계(Offset) 판단 조건
정기결제 상계는 아래 조건이 **모두** 충족될 때만 의미 있음:
- 해당 거래처의 APPROVED 상태 payables가 1건 이상 존재 (결제할 금액이 0원 초과)
- 해당 거래처의 `costs.amount < 0`이고 아직 어떤 payable에도 할당되지 않은 비용이 존재

### 5.5 정기결제 지급 실행 결과
`runPeriodicConsolidationSingle(vendorName)` 실행 시:
1. 선택된 거래처의 APPROVED payables를 1건의 일괄 payment로 집계
2. `payments` 레코드 생성 (pay_status='PAID', pay_method='TRANSFER')
3. 해당 payables 상태 → PAID 전환
4. 지급내역 관리 탭으로 결과 이동

## 6. 지급처리 (결제 실행)

### 6.1 화면 목적
APPROVED 상태의 payable에 대해 **실제 이체를 실행**하고 payments 레코드를 생성한다.

### 6.2 처리 결과
- `payments` 레코드 생성 (pay_status='PAID')
- `payment_payable_allocations` 생성 (payable ↔ payment 1:1 연결)
- payable.paid_amount 업데이트
- payable.pbl_payable_status → PAID 전환

### 6.3 단건/일괄 지급 선택 기준

| 구분 | 진입 경로 |
|---|---|
| 단건 지급 | AP 우측 패널 단건 선택 → 하단 지급 블록 |
| 일괄 지급 | AP 리스트 체크박스 다건 선택 → 하단 지급 블록 |
| 정기 일괄 | 정기결제 탭 우측 하단 지급 블록 |

## 7. 미지급 관리 (Unpaid Management)

### 7.1 화면 목적
발주서 기반 건의 미지급 잔액을 집계하여 리스크 거래처를 모니터링한다.

### 7.2 데이터 로직
```
미지급 잔액 = 계약/발주 총액 (total) - 기지급 대금 (paid)
```
- `미지급 잔액 = 0`인 건은 리스트에서 제외 (완납)
- `미지급 잔액 > 2,000만원` 시 UI 강조 (미지급 위험 경보)

### 7.3 UI 구조 (Split-View)
- **좌측 패널 (리스트)**: 발생 출처(Origin) 태그 / 거래처·사업자번호 / 담당자 / 계약·발주 총액 / 기지급 대금 / **미지급 잔액** (강조색)
- **우측 패널 (상세)**: 미지급 한도 현황 및 알림 상세. 선택 미클릭 시 "목록에서 조회할 건을 선택하세요" 안내

### 7.4 발생 출처(Origin) 태그 분류

| 태그 | 의미 |
|---|---|
| `[PO]` | 발주서 기반 원자재/부품/물품 구매 |
| `[PROJECT]` | 프로젝트 기반 외주개발·공사·설계 등 |
| `[SHIPMENT]` | 화물운송 (용달, 제품 정기운송 등) |
| `[INDIRECT]` | 간접공통비 (세무자문, 자체운영비 등) |

## 8. 지급내역 리스트

### 8.1 화면 목적
**지급 완료된 payments 이력**을 조회한다. (Read-Only)

### 8.2 조회 필터

| 필터 | 유형 |
|---|---|
| 기간별 조회 | 전체 / 최근 1개월 / 최근 3개월 / 최근 6개월 / 직접 입력 |
| 지급일 커스텀 | 시작일 ~ 종료일 |
| 지급 수단 | 전체 / 계좌이체 / 법인카드 / 현금 |
| 거래처별 그룹보기 | 토글 |

### 8.3 리스트 컬럼

| 컬럼 | 데이터 소스 | 비고 |
|---|---|---|
| 결제일 | `payments.pay_paid_at` | |
| 결제 수단 | `payments.pay_method` | TRANSFER / CARD / CASH 배지 표시 |
| 수취인 (가맹점) | `payments.vendor_name` | 1회성 미등록 업체: "미등록 1회성" 배지 표시 |
| 적요 / 구매 내역 | `payments.description` | |
| 결제 금액 | `payments.amount` | |
| 증빙 | `payments.has_doc` | 첨부됨 / 미첨부 표시 |

### 8.4 지급내역 상세 패널 (우측)

| 섹션 | 내용 |
|---|---|
| 기본 정보 | 결제일 / 결제수단 / 수취인 / 결제금액 / 적요 |
| 증빙 첨부 상태 | 첨부됨 (emerald), 미첨부 (amber) 상태 표시 |
| 사후 증빙 관리 | [+ 파일 직접 추가] 버튼 → 재무담당자가 사후 직접 파일 업로드 가능 |
| 세금계산서 대사 | 대사 화면(recon.html)으로 이동 안내 |
| 정산조정 발의 | [+ 정산조정(환수 등) 발의] 버튼 → 모달 팝업으로 즉시 발의 |

## 10. 권한 정책 (1차 범위)

| 역할 | 가능 액션 | 통제 대상 |
|---|---|---|
| 재무 담당자 | 지급 실행 (payments 생성), 정기결제 집계·실행 | 승인된(APPROVED) 건에 대한 실무 이체 및 내역 관리 |
| 승인자 (대표) | payable 승인 / 반려 | 자금 이동을 위한 통제소 |
| 일반 담당자 | 지급 요청 생성 (payable CREATED) | 발주서 기반 또는 기타 부대비용 기안 |

> **핵심 원칙**: 자금 지급이 일어나는 과정에서 반드시 대표 승인(APPROVED) 또는 반려(REJECTED) 절차를 거치도록 통제된다.

## 11. 관련 엔티티 요약
