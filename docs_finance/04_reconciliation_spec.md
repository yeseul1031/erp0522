# 대사·리콘실리에이션 화면 기획 명세 (Reconciliation Spec)

> **문서 버전**: v2.0 (시뮬레이션 기준 전면 갱신 — recon.html 반영)
> **참조**: recon.html (세금계산서 대사 섹션), erp_finance_schema.sql
> **최종 갱신일**: 2026-04-09

---

## 1. 업무 목적

시스템 거래(payments)와 외부자료(전자세금계산서)를 비교하여 **불일치를 식별하고 해소**한다.

**1차 범위: 세금계산서 대사 중심**

**포함 업무 (현행 기준)**
1. 세금계산서 대사 리스트 (듀얼 스트림 뷰)
2. 상태별 탭 필터링
3. 자동/수동 매칭 처리
4. 불일치 건 정산조정 발의 연동

**현재 범위 내 원칙**
- 대사의 기본 단위: **세금계산서(tax_invoices)** 기준
- 국세청 데이터(Hometax)와 ERP 시스템 데이터(payments)를 **좌/우 병렬 배치(Dual-Stream)**로 시각적 직접 비교
- 데이터 수집 방식: **국세청 홈택스 엑셀 파일 직접 업로드** (API 연동 아님)
- 대사 상태값: `UNMATCHED` / `PARTIAL` / `MATCHED` (ti_recon_status)

## 3. 세금계산서 대사 화면

### 3.1 화면 목적
수신된 전자세금계산서(Hometax)와 ERP 내 지급내역을 **좌우 병렬 비교**하여 불일치를 즉각 식별하고 처리한다.

### 3.2 상단 헤더 액션 버튼

| 버튼 | 기능 | 디자인 |
|---|---|---|
| **국세청 엑셀 업로드** | 홈택스 엑셀 파일 업로드 → 데이터 파싱 및 화면 갱신 | `bg-emerald-600` |
| **샘플 데이터 시뮬레이션** | 가상 Hometax + ERP 데이터를 즉시 로드 (시뮬레이션용) | `bg-indigo-50` |
| **Auto-Match (일괄 대사)** | 거래처명 및 금액 일치 건 자동 'MATCHED' 처리 | `bg-indigo-600` |

> 엑셀 업로드 전까지는 빈 화면 안내 메시지 표시

### 3.3 상태별 탭 (Sub Navigation)

| 탭 | 필터 조건 | 특징 |
|---|---|---|
| 전체 | 모든 데이터 | 기본 선택값 |
| 불일치 | `status === 'UNMATCHED'` | 빨간색 뱃지 + 애니메이션 적용 |
| 부분일치 | `status === 'PARTIAL'` | |
| 대사완료 | `status === 'MATCHED'` | |

기본 표시 탭: **전체**

## 4. 듀얼 스트림 뷰 (Dual-Stream Split View)

### 4.1 좌측 패널 — 국세청 수집 데이터 (Hometax)

**역할**: 외부 원천 데이터 (Original Truth)

각 카드에 표시되는 정보:
- 발행일 (`issue_dt`)
- 대사 상태 배지 (`status`)
- 공급사명 (`supplier`)
- 승인번호 (`approval_no`) — 국세청 식별자
- 합계금액 (`total_amount`)

브릿지 인디케이터: MATCHED/PARTIAL 건에는 카드 우측에 수평 라인 표시 (매칭 연결 시각화)

### 4.2 우측 패널 — ERP 시스템 기록 (System Data)

**역할**: 내부 지급 원장 (ERP 데이터)

각 카드에 표시되는 정보:
- 결제일 (`pay_date`)
- 대사 상태 배지
- [정산조정 발의] 버튼 — UNMATCHED/PARTIAL 건에만 표출
- 공급사/수취인명
- 연결 승인번호 (매칭 시)
- 시스템 기록 금액
- **⚠️ DIFF DETECTED**: 국세청 금액과 차이가 있을 경우 금액 빨간색 강조 + 차이 금액 툴팁

### 4.3 센터 구분선
- 좌/우 패널 사이 수직 구분선 표시 (PC 화면)
- 매칭된 카드 쌍은 브릿지 라인으로 연결

## 5. 대사처리 (매칭 실행)

### 5.1 Auto-Match 동작
```
[Auto-Match] 버튼 클릭
  │
  ▼
공급사명 + 합계금액이 100% 일치하는 Hometax ↔ System 쌍 탐색
  │
  ▼
일치 쌍 → status 'MATCHED' 로 업데이트
  │
  ▼
화면 즉시 반영 (탭 필터 및 건수 뱃지 갱신)
```

### 5.2 수동 매칭 (정산조정 경로)
- 불일치/부분일치 건의 우측 패널 카드에서 **[정산조정 발의]** 버튼 클릭
- 모달 팝업으로 정산조정 생성 (origin 자동 매핑: `TI_[id]`)
- 발의 데이터는 localStorage를 통해 정산조정 관리 탭에 실시간 반영

### 5.3 대사 상태 전이

| 조건 | 상태 |
|---|---|
| 매칭 없음 | UNMATCHED |
| 일부 매칭 | PARTIAL |
| 전액 매칭 | MATCHED |

### 5.4 불일치 시 액션

| 상황 | 처리 방향 |
|---|---|
| 세금계산서 금액 > 시스템 기록 | 정산조정 발의 (환수 또는 추가 payment 매칭) |
| 금액 차이 발생 | ERP 카드에 빨간색 금액 + DIFF DETECTED 경고 표시 |
| 수정/취소 세금계산서 수신 | `ti_status = MODIFIED/CANCELLED` 업데이트 후 재검토 |

> 실제 조정 행위(환수/반환/추가지급)는 **정산조정관리(05번 문서)**에서 수행

---

## 6. 경계 및 통제 원칙

- 대사 결과 조정이 필요하다는 **판단은 여기서** 하지만
- 실제 환수/반환/추가 입출금 처리 **행위는 정산조정관리(05번 문서)**에서 독립 수행
- 자금 변동이 수반되는 조정은 **대표의 명시적 승인**을 통해서만 최종 확정
- 현금흐름 대사, 은행 계좌 잔액 대사 → 후속 확장

## 7. 관련 엔티티 요약

| 엔티티 | 역할 |
|---|---|
| `tax_invoices` | 전자세금계산서 정본 |
| `tax_invoice_payment_allocations` | 세금계산서 ↔ 지급 대사 배분 (부분 매칭 허용) |
| `payments` | 실지급 결과 (대사 대상) |
| `payables` | 지급 단위 (대사 연결 경로: pay→payable→invoice→cost) |
