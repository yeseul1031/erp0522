# [기능 기획서] 입출고 관리 (SCR-LOGI-001) - 전면 개정판

---

## 1. 요구사항 정의 (Requirement Definition)
- **기능 목적**: 발주 이후의 물품 흐름(입고-재고-출고)을 가시화하고 기록의 정확성을 확보함.
### 1.2 사용 주체
- **구매 담당자 (실무자)**: 본인이 담당하는 품목의 실물 입/출고 수량을 직접 기록한다. (Primary User)
- **연관 담당자 및 관리자**: 프로젝트 및 발주 진행 현황을 실시간으로 모니터링한다. (Viewer)
- **범위**: PO 기반 입고수량 입력, 프로젝트 배분 기반 출고실행 입력, 가용재고 계산 및 **물류 재고 원장(Inventory Ledger) 연동**.
- **참조 ADR**: [ADR-008] 발주 이후 물류 4축 모델(Physical/Shipment/Job/Request) 준수. [ADR-013] 문서/실물/작업 단위 분리.
- **제외 범위**: 바코드 실시간 연동, 창고 위치별(Bin) 상세 관리, 물류비 정산 로직.
- **제약 사항**:
    - 입고 처리는 발주서 상태가 `ACCEPTED`(승인완료/이행중)일 때 가능함.
    - **특이사항**: 내부 결재 단계인 `SENT`(승인요청중) 상태에서는 데이터 오염 방지를 위해 모든 입력 필드가 잠금(Lock) 처리됨.
    - 출고 처리는 입고된 재고가 존재하는 품목에 한함.
- **성공 기준**: 
    - 모든 발주 품목의 `pol_in_qty`가 `pol_qty`와 일치하여 '입고 완료' 상태가 됨.
    - 프로젝트별 할당 수량이 모두 출고되어 가용 재고가 0이 됨.

- **기능 동작**:

## 3. 화면 정의 (Screen Definition)
- **화면 이동**: 
    - **입출고 관리**: 메인 메뉴를 통해 진입 시 `ACTIVE` 프로젝트 품목만 기본 리스트업.
    - **프로젝트 관리**: 각 프로젝트 상세/내역의 [입출고내역 조회] 버튼을 통해 특정 프로젝트 컨텍스트로 진입.
- **조회 전용 모드 (History View)**: 프로젝트 관리 화면에서 종료된 프로젝트(`p_status=CLOSED`)를 통해 진입한 경우, 모든 입력 필드를 Read-only로 고정하고 '이력 조회 모드' 배지를 표시함.
- **오류 메시지**: 
    - "권한이 없습니다", "발주 수량을 초과할 수 없습니다", "가용 재고가 부족합니다".
- **진입 및 이탈 조건**: 
    - 진입: 유효한 사용자 세션 보유 시.
    - 이탈: 입력값 변경 시 자동 저장되므로 별도의 저장 확인 없이 이탈 가능.

## 4. 데이터 정의 (Data Definition)
- **데이터 항목 및 의미**:
    - `pol_in_qty`: 창고에 도착하여 인수가 확인된 수량.
    - `poa_out_qty`: 창고에서 프로젝트 현장으로 반출된 수량.
- **출처**: `purchase_orders`, `po_lines`, `po_allocations` (정본).
- **생성/변경 기준**: 
    - 생성: PO 확정 시 기본값 0으로 생성.
    - 변경: 담당자가 화면에서 수동 입력 시 **실시간 자동 저장(Auto-save)** 로직에 의해 즉시 업데이트.
- **삭제/비활성화 기준**: 데이터 삭제는 원칙적으로 불가하며, PO 취소 시 관련 입출고 기록은 '무효' 처리됨.
- **데이터 관계**: 
    - 1 `po_line` : N `po_allocations` (할당된 프로젝트 수만큼 존재).
    - `pol_in_qty` (부모) ≥ `sum(poa_out_qty)` (자식 합계).

## 5. 상태 정의 (State Definition)
### 5.1 품목별 진행 상태 (scl_status 참조)
- **IN_PROGRESS (이행중)**: 발주 완료 후 물품 도착을 대기하거나 입/출고가 진행 중인 상태. (정본: `scl_status='IN_PROGRESS'`)
- **RECEIVED (입고완료)**: 입고/수령이 완료된 상태. (정본: `sourcing_case_lines.scl_status='RECEIVED'`)

### 5.2 발주서 마스터 상태 (purchase_orders.po_status 참조)
- **SENT (승인요청중)**: 담당자가 결재 요청을 상신한 상태. (DDL: `po_status='SENT'`, 시스템 잠금)
- **ACCEPTED (승인완료/이행중)**: 승인 완료 후 업체 발송 및 이행 단계. (DDL: `po_status='ACCEPTED'`, 입고 가능)
- **CLOSED (종료)**: 발주 실행과 정산이 운영상 종료된 최종 상태. (DDL: `po_status='CLOSED'`)
- **CANCELLED (취소)**: 발주 취소. (DDL: `po_status='CANCELLED'`)

### 5.3 상태별 가능/불가능 행동
| 상태 | 가능 행동 | 불가능 행동 |
| :--- | :--- | :--- |
| ACCEPTED | 수량 입력/수정, 자동 저장 | (없음) |
| SENT / CLOSED | 데이터 조회, 엑셀 다운로드 | 수량 수정 및 입출고 실행 (결재 대기 또는 종료 상태) |

## 6. 업무 규칙 (Business Rules)
### 6.1 권한 및 편집 제한 (Ownership)
- **원칙**: 로그인한 사용자 ID가 해당 품목의 실무 담당자(`sc_assignee_a_sn`)인 경우에만 수량 및 비고 수정이 가능하다. (본인 소유 품목 혹은 협업 요청을 수락하여 배정된 품목 포함)
- **Read-only 대상 (수정 불가)**:
    - 실무 담당자가 아닌 프로젝트 내 타 담당자 및 연관 담당자.
    - 중간 관리자 및 대표이사. (모니터링 용도)
- **UI 처리**: 수정 권한이 없는 경우 입력 필드를 `Read-only`로 전환하고, 행(Row)에 '잠금(Lock)' 시각 효과를 적용한다.

### 6.2 수량 검증 로직 (Validation)
- **계산 규칙**: 가용재고 = `pol_in_qty` - `sum(poa_out_qty)`.
- **승인 조건**: 별도 승인 절차 없음 (입력 즉시 반영).

### 6.3 저장 방식 (Auto-save)
- **방식**: **실시간 자동 저장(Auto-save)** 방식 적용. 입력 필드 변경 후 포커스 아웃 또는 일정 시간(1s) 경과 시 데이터 반영 및 토스트 알림 표시.

### 6.4 권한 조건 (Access Control)
- **작성(Write)**: 품목별 담당자(`sc_assignee_a_sn`) 본인. (진행 중인 프로젝트에 한함)
- **조회(Read)**: 연관 담당자, 중간 관리자, 대표이사 등 전사 권한자.
- **노출 정책 (Visibility)**:
    - **기본 노출**: 프로젝트 상태가 `ACTIVE` 또는 `PRE_CONTRACT`인 건만 리스트에 표시.
    - **노출 제외**: `CLOSED` 또는 `CANCELLED` 프로젝트는 리스트에서 제외하여 업무 노이즈 최소화.
    - **과거 이력 조회**: 제외된 건은 '프로젝트 관리' 화면의 링크를 통해 특정 프로젝트 단위로만 조회 가능.
- **중복 처리**: 동일 `pol_sn`에 대해 동시 수정 시 최종 저장 시점의 값으로 덮어씀 (Last-win).
- **수정 가능**: 품목 상태가 `IN_PROGRESS`이고, 발주서 상태가 `ACCEPTED`인 경우.
- **수정 불가**: 정본 데이터 보호를 위해 다음 중 하나에 해당하는 경우 필드를 비활성화(Read-only)함.
    - 발주서 상태가 **`SENT`** (결재 대기 중)
    - 발주서 상태가 **`CLOSED / CANCELLED`** (종료/취소)
    - 품목 상태가 **`RECEIVED`** (입고 완료)
- **기술적 데이터 트리거 (Data Sync & Ledger)**:
    - 수량 저장 시 **`po_lines`의 편의 필드** 업데이트와 동시에 다음 작업을 수행함.
    - **원장 생성**: `inventory_operations`, `inventory_operation_lines`, `inventory_units`(입고 시) 또는 `deliveries`(출고 시) 생성.
    - **헤더 동기화**: `po_lines` 수량 변경에 따라 `purchase_orders.po_total_price` 및 `po_total_tax` 캐시 필드를 실시간 재계산하여 동기화함. (DDL 준수 사항)
    - **상태 업데이트**: 수량 충족 시 `sourcing_case_lines.scl_status`를 `RECEIVED`로 변경.

## 7. 유스케이스 및 시나리오 (Use Case / Scenario)
- **정상 흐름 (9대 요소)**:
    1. **시작**: 물품 도착 확인.
    2. **입력**: 도착 수량 5개 입력.
    3. **행동**: 입력 필드에서 포커스 아웃(Focus-out) 또는 1초 대기.
    4. **로직**: 자동 저장 및 물류 원장(`IO`, `IU`) 생성. `5 <= (발주 10 - 기입고 0)` 검증 통과.
    5. **상태**: 품목 상태 `IN_PROGRESS` 유지 (발주 상태 `ACCEPTED`).
    6. **변경**: `pol_in_qty`를 5로 DB 업데이트.
    7. **결과**: "저장 완료" 토스트 알림 및 가용재고 5개 즉시 반영.
    8. **종료**: 입고 리스트에 반영 완료 확인.
    9. **대체**: 발주 수량보다 초과 입고된 경우, 저장을 허용하되 UI에서 '초과 입고(OVER)' 상태를 시각적으로 강조함.

## 8. 예외 케이스 (Exceptions)
- **상태 오류 (CLOSED/CANCELLED)**: 이미 종료되거나 취소된 발주서에 접근하여 수정을 시도할 경우 "처리할 수 없는 상태의 발주입니다" 안내.
- **수량 검증 오류 (Inventory Check)**: 
    - **입고**: 발주 수량 초과는 허용(MOQ 등 대응)하나, 음수 입력은 차단함.
    - **출고**: `출고 실행 수량 > 가용 재고(입고 완료 수량 - 기출고 수량)`인 경우, 저장을 차단하고 "가용 재고를 초과하여 출고할 수 없습니다" 에러 토스트 반환.
- **권한 문제 (API Level)**: 
    - **UI**: 담당자가 아닌 경우 입력 필드를 비활성화(Lock)하여 접근을 원천 차단함.
    - **API**: 사용자가 부정한 방법으로 수정을 요청할 경우, 서버에서 담당자 여부를 재검증하여 저장 거부 및 "권한 없음" 에러 응답.
- **네트워크 오류**: 자동 저장 중 통신이 끊긴 경우 "네트워크 연결을 확인해주세요" 안내 후 재시도 유도.

## 9. 입출력 요구사항 (I/O Requirements)
- **입력 데이터 (Request Body)**: 
    - `target_sn`: `pol_sn` (입고 대상) 또는 `poa_sn` (출고 대상)
    - `qty_value`: `pol_in_qty` 또는 `poa_out_qty` (입력된 수량값)
    - `event_dt`: `pol_in_dt` 또는 `poa_out_dt` (업무 발생 일시)
    - `note`: `pol_note` 또는 `poa_note` (비고/특이사항)
- **출력 데이터 (Response Body)**: 
    - `success_flag`: 처리 성공 여부 (boolean)
    - `calculated_balance`: 계산된 가용 재고 (`pol_in_qty` - `sum(poa_out_qty)`)
    - `po_status`: (Optional) 변경된 발주서 마스터 상태
    - `scl_status`: (Optional) 변경된 품목 진행 상태 (`IN_PROGRESS` / `RECEIVED`)
    - `io_sn`: 생성된 물류 재고 작업 PK (`inventory_operations`)
- **상태 변화**: 입력된 `qty_value`에 따라 정본 테이블(`purchase_orders`, `po_lines`, `po_allocations`)의 상태 필드를 실시간으로 재계산하여 반환함.
