# [기능 기획서] 견적발주 자동송부 (PROC-RFQ-AUTO-001)

---

## 1. 요구사항 정의 (Requirement Definition)

### 1.1 기능 목적
- 구매 담당자가 선정한 다수의 품목(Sourcing Case Lines)과 업체(Parties)에 대해 견적 요청(RFQ) 및 발주(PO) 프로세스를 자동화하여 업무 효율성을 극대화함.
- 업체 측에 고유 링크(URL)를 제공하여 직접 데이터를 입력하게 함으로써 데이터 입력의 정확성을 높이고 담당자의 전입(Transcribe) 리드타임을 제거함.

### 1.2 사용 주체
- **구매 담당자 (Manager)**: 견적 요청 대상을 선정하고, 시스템을 통해 자동 송부를 실행하며, 업체별 회신 내역을 비교/검토함.
- **협력사 담당자 (Vendor)**: 이메일로 수신된 링크를 통해 시스템에 접속하여 견적가, 공급 가능 여부, 납기 등을 직접 입력함.

### 1.3 범위 및 제약
- **범위**: RFQ 생성 및 송부, 외부 링크 기반 업체 응답 수집, 응답 데이터 자동 동기화.
- **참조 DDL**: `rfqs`, `rfq_lines`, `sourcing_case_lines`, `parties`, `assignees`.
- **제외 범위**: 실제 메일 서버(SMTP) 구축 상세, PDF 엔진 구현 방식, 업체 회원가입 프로세스(비회원 링크 인증 방식).

## 2. 기능 정의 (Functional Definition)

### 2.1 주요 기능 동작
1.  **RFQ 생성 및 일괄 송부**: 선정된 `sourcing_case_lines`를 기반으로 업체별 `rfqs` 헤더와 `rfq_lines`를 자동 생성하고 알림(이메일/알림톡)을 발송함.
2.  **외부 링크 인증 및 조회**: 업체 담당자는 로그인 없이 고유 토큰이 포함된 링크를 통해 본인 업체에 할당된 견적 요청 내역을 조회함.
3.  **견적 회신 입력**: 업체는 각 라인별로 '공급 가능/대체 제안/지연/공급 불가' 상태를 선택하고 단가 및 비고를 입력함.
4.  **자동 정합성 체크**: 요청 수량과 공급 가능 수량이 불일치하거나 필수 입력 항목이 누락된 경우 제출을 차단함.
5.  **회신 데이터 동기화**: 업체가 제출 완료 시 ERP 내 `rfqs.rfq_status`가 `REPLIED`로 변경되며, 입력된 값이 `rfq_lines`에 즉시 반영됨.

### 2.2 업무 규칙 (Business Rules)
- **DDL 정합성**: 모든 상태값은 DDL의 `ENUM` 정의를 엄격히 준수함. (`rfq_status`, `po_status`, `scl_status`)
- **링크 유효성**: 발행된 외부 링크는 보안 및 데이터 관리 정합성을 위해 발송일로부터 14일(2주) 동안만 유효하며, 이후 자동 만료됨.
- **재발송(Resend) 정책**: 시스템 오류로 인한 발송 실패 또는 유효 기간 내 업체의 요청 시 **[재발송]** 기능을 통해 동일한 내역을 다시 보낼 수 있음. 단, 이는 링크의 **유효 기간을 연장하는 기능은 아님**.
- **수정 제한**: 업체가 제출을 완료한(`REPLIED`) 건은 업체 측에서 더 이상 수정할 수 없음. 수정이 필요한 경우 구매 담당자의 '회신 취소' 처리가 선행되어야 함.
- **담당자 소유권**: `rfqs.rfq_a_sn`은 송부를 실행한 담당자로 자동 지정됨.
- **중복 송부 및 관리**: 동일한 `sourcing_case_lines`(SCL) 및 업체(`rfq_pt_sn`) 조합으로 중복 송부가 가능함. 이 경우, 가장 최근에 회신된(`REPLIED`) 견적 데이터를 최종 단가 비교의 정본으로 채택함.

## 3. 화면 정의 (Screen Definition)

### 3.1 구매 담당자 화면 (`index.html` 기반)
- **견적 현황 리스트**: 업체명, 요청일, 회신일, 진행 상태(`SENT`, `REPLIED`, `DECLINED`)를 표시.
- **액션 바**: [일괄 재송부], [만료건 삭제], [단가 비교] 버튼 배치.
- **상태 배지**:
    - `SENT`: 견적 진행중 (파란색)
    - `REPLIED`: 회신 완료 (초록색)
    - `EXPIRED`: 기한 만료 (회색/Lock 아이콘)

### 3.3 발주 장바구니 동기화 (PO Basket Sync)
- **장바구니 자동 로드**: 담당자가 '가격정보' 탭 진입 시, 백엔드로부터 `po_status != 'CANCELLED'`인 모든 발주 데이터를 수신함.
- **DRAFT 상태 표출**: 현재 `po_status = 'DRAFT'`(승인 기안 전)인 품목들은 장바구니에 담긴 상태로 즉시 화면에 렌더링함.
- **중복 발주 방지 (Block)**: 이미 승인 프로세스가 진행 중이거나 완료된 품목(`po_status`가 `SENT`, `ACCEPTED`, `CLOSED` 중 하나인 경우)은 가격정보 리스트에서 회색으로 블락 처리하고 선택을 차단함.

### 3.2 협력사 응답 화면 (`vendor.html` 기반)
- **이메일 프리뷰**: 메일 본문 내 [견적 작성하기] 버튼 포함.
- **견적 입력 폼**: 
    - 상단: 구매사 정보 및 요청 요약 (Total Amount 자동 계산).
    - 본문: 품목 리스트 (상품명, 규격, 요청수량, **공급상태 선택**, 단가 입력, 비고).
    - 공급상태(Supply Status): `OK`(정상), `ALT`(대체제안), `DELAY`(납기지연), `N/A`(공급불가).

## 4. 데이터 정의 (Data Definition)

### 4.1 핵심 엔티티 매핑
- **RFQ 헤더 (`rfqs`)**:
    - `rfq_status`: `DRAFT` -> `SENT` -> `REPLIED` / `DECLINED`.
    - `rfq_issued_at`: 송부 실행 시각.
    - `rfq_replied_at`: 업체 제출 시각.
- **RFQ 라인 (`rfq_lines`)**:
    - `rfql_item_qty`: 업체가 응답한 공급 가능 수량 (요청 수량과 다를 수 있음).
    - `rfql_unit_price`: 업체 응답 단가.
    - `rfql_vat_rate`: 부가세율 (기본 0.1).
- **수급 라인 (`sourcing_case_lines`)**:
    - `scl_status`: RFQ 송부 시 `QUOTING`으로 전환.

### 4.2 데이터 흐름
1.  Manager: SCL 선택 -> RFQ 생성 (`DRAFT`) -> 송부 클릭 (`SENT`).
2.  System: 고유 토큰 생성 -> 메일 발송 -> `rfq_issued_at` 기록.
3.  Vendor: 링크 접속 -> 데이터 입력 -> 제출 클릭.
4.  System: `rfq_lines` 업데이트 -> `rfq_status`를 `REPLIED`로 변경 -> Manager에게 알림.

## 5. 상태 정의 (State Definition)

### 5.1 RFQ 마스터 상태 (`rfqs.rfq_status`)
| 상태명 | 의미 | UI 표시 | 비고 |
| :--- | :--- | :--- | :--- |
| **DRAFT** | 작성 중 | 임시저장 | 송부 전 단계 |
| **SENT** | 송부 완료 | 회신 대기 | 업체 측 링크 활성화 상태 |
| **REPLIED** | 회신 완료 | 회신 완료 | 업체 입력 데이터 ERP 반영됨 |
| **CANCELLED** | 요청 취소 | 요청 취소 | 구매 담당자가 수동으로 중단 |
| **CLOSED** | 종료 | 종료 | 최종 발주 채택 또는 반려 시 |

### 5.2 발주서 마스터 상태 (`purchase_orders.po_status`)
| 상태명 | 의미 | 화면 대응 | 비고 |
| :--- | :--- | :--- | :--- |
| **DRAFT** | 발주서 작성중 | 장바구니 담김 | 가격정보 탭에서 언제든 수정 가능 |
| **SENT** | 승인 기안/요청중 | 블락 (Lock) | 수정 불가, 승인 대기 단계 |
| **ACCEPTED** | 승인완료/이행중 | 블락 (Lock) | 수정 불가, 중복 발주 방지 대상 |
| **CLOSED** | 종료 | 블락 (Lock) | 최종 납품/정산 완료 건 |
| **CANCELLED** | 발주 취소 | 다시 선택 가능 | 장바구니에서 제외됨 |

## 6. 예외 시나리오 및 대응 (Critical Exceptions)

### 6.1 링크 관련 예외
- **링크 만료 (EXPIRED)**: 발송 후 14일이 경과하면 링크는 자동 무효화됨. 업체가 만료된 링크 접속 시 "견적 요청 기한(14일)이 만료되었습니다. 담당자에게 문의하세요" 안내 문구와 담당자 연락처 노출.
- **부정한 접근 (Unauthorized)**: 토큰이 유효하지 않거나 일치하지 않는 경우 접근 차단 (403 Forbidden).

### 6.2 데이터 입력 예외
- **부분 견적 (Partial Quote)**: 일부 품목만 견적이 가능한 경우, 불가한 품목은 `N/A` 상태를 선택하게 유도. 모든 라인에 대해 상태가 선택되어야만 제출 가능.
- **수량 부족 (Shortage)**: 요청 수량보다 적은 수량만 공급 가능한 경우, `rfql_item_qty` 수정 시 '수량 부족 사유'를 비고(`rfql_note`)에 작성하도록 강제(Validation).
- **대체 제안 (Alternative)**: 요청한 품목과 다른 모델을 제안하는 경우, 상태를 `ALT`로 변경하고 대체 모델명을 비고에 작성하게 함.

### 6.3 프로세스 제어 규칙
- **중복 송부 허용**: 동일 SCL에 대해 동일/타 업체로 여러 건의 RFQ 송부가 가능함. 가장 최근에 `REPLIED`된 데이터를 정본으로 사용함.
- **중복 발주 원천 차단**: 품목(SCL)이 이미 승인/완료 단계의 발주서(`po_status` IN `SENT`, `ACCEPTED`, `CLOSED`)에 포함된 경우, 가격정보 화면에서 해당 품목의 선택 기능을 비활성화(Read-only 및 Gray-out)하여 중복 발주를 방지함.
- **송부 후 데이터 변경**: 담당자가 RFQ 송부 후 ERP에서 해당 SCL의 스펙을 수정할 경우, 업체 화면에 "요청 사항이 변경되었습니다. 페이지를 새로고침 하세요" 알림 표시.

### 6.4 시스템 및 네트워크 예외
- **메일 발송 실패**: SMTP 오류 등으로 발송 실패 시, 해당 RFQ를 `DRAFT`로 유지하고 담당자에게 "발송 실패" 로그와 재시도 버튼 제공.
- **제출 중 세션 끊김**: 업체가 작성 중 브라우저를 닫더라도 입력 데이터는 'Draft'로 임시 저장되어 재접속 시 복구되어야 함 (LocalStorage 또는 주기적 서버 저장).

## 7. 입출력 요구사항 (I/O Requirements)

### 7.1 송부 API (Manager -> Server)
- **Request**: `scl_sns[]`, `vendor_sns[]`, `due_date`, `message`.
- **Logic**: `rfqs` 생성 (Vendor 수만큼), 각 `rfq_lines` 생성 (SCL 수만큼), 이메일 큐 등록.

### 7.2 업체 응답 API (Vendor -> Server)
- **Request**: `token`, `lines: { rfql_sn, status, qty, price, note }[]`.
- **Validation**: 토큰 유효성, 필수값 체크, 수량/단가 양수 체크.
- **Result**: `rfq_status` 업데이트 및 `rfq_replied_at` 기록.
