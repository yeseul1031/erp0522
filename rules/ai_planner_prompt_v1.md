# AI Planner Golden Prompt Template (v2.1)

이 템플릿은 AI(Antigravity)에게 `planner_rule.md` 표준에 부합하는 완벽한 기능 기획서를 요청하기 위한 표준 가이드입니다. 아래 지침은 AI가 자의적인 해석을 배제하고 **정본(Source of Truth)**에만 근거하도록 강제합니다.

---

## [대상 기능명] 기능 기획서 작성 요청

### 1. 기본 원칙 (Strict Consistency & DDL Primacy)
- **DDL 최우선 원칙**: 모든 기획의 근거는 **DDL > ADR > Docs** 순이다. Docs에 기술된 용어라도 DDL의 ENUM 값이나 필드명과 다를 경우, 무조건 **DDL의 명칭을 정본으로 채택**한다.
- **용어 엄격성 (Zero Tolerance)**: 자의적인 추상화나 서비스 용어 사용을 절대 금지한다. (예: DDL에 `IN_PROGRESS`로 되어 있다면 `ACTIVE`나 `진행중`이라는 표현 대신 반드시 `IN_PROGRESS`를 명시할 것)
- **아키텍처 정합성**: 단순 데이터 수정을 넘어, 관련 **ADR**에서 결정된 아키텍처 모델(예: ADR-008의 물류 4축 모델)을 설계에 반드시 반영해야 한다.

### 2. 작성 전 필수 기술 검토 (Pre-Flight Check)
- [ ] **DDL ENUM 추출**: 관련 테이블의 상태 필드(ENUM) 값을 직접 확인하고 기획서에 그대로 인용했는가?
- [ ] **ADR 패턴 확인**: 해당 도메인에 적용된 핵심 설계 원칙(ADR)이 무엇인지 파악했는가?
- [ ] **필드명 매핑**: API I/O 정의 시 DDL 컬럼명(`pol_sn`, `iu_status` 등)과 100% 일치하는가?

### 3. 권한 및 데이터 흐름 (Data Flow & Ownership)
- **작성/조회 권한**: DDL 내 담당자 필드(예: `sc_assignee_a_sn`)와 연동하여 정의하고, 권한 없는 사용자에 대한 `Read-only` 및 시각적 잠금(Lock) 처리를 구체화할 것.
- **데이터 트리거**: 화면상의 입력이 백엔드에서 어떤 **원장 테이블(Ledger)**을 생성/수정하는지 명시할 것 (예: 수량 입력 시 `inventory_operations` 자동 생성).

### 4. 시나리오 및 예외 처리 (Use Case)
- **9대 요소 준수**: `planner_rule.md` 8.2절의 9대 요소를 갖추되, **UI 동작(포커스 아웃 등)**과 **시스템 로직(DB 트랜잭션)**을 엄격히 분리할 것.
- **실시간 저장**: '실시간 자동 저장' 정책 시 '저장 버튼' UI가 절대 포함되지 않도록 이중 체크할 것.

### 5. 최종 검수 리스트 (Self-Audit Checklist)
AI는 최종 산출물을 제출하기 전 아래 질문에 "YES"라고 답할 수 있어야 함:
1. **"DDL에 없는 상태명이나 필드명을 단 하나라도 사용했는가?"** (NO여야 함)
2. **"관련 ADR의 아키텍처 모델을 기획서에 녹여냈는가?"** (YES여야 함)
3. **"입력 데이터 필드명이 DDL 컬럼명과 정확히 일치하는가?"** (YES여야 함)

### 6. 산출물 저장
- `spec/functional_spec_[기능ID].md` 경로에 저장하고, 변경 사항이 정본(DDL/ADR)과 어떻게 결합되는지 요약 보고할 것.
