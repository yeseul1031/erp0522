# [기획팀 내부 가이드] 기능 기획 프로세스 및 산출물 표준 (v1.0)

본 문서는 개발팀의 산출물 완료 기준을 충족하면서도, 기획팀이 실무에서 논리적인 순서에 따라 업무를 진행할 수 있도록 재구성한 가이드입니다.

---

## 📅 기획 진행 로드맵

| 단계 | 주요 활동 | 핵심 산출물 |
| :--- | :--- | :--- |
| **Phase 1** | 요구사항 및 범위 확정 | 요구사항 정의서 |
| **Phase 2** | 정책 및 상태 설계 | 업무 규칙서, 상태 정의서 |
| **Phase 3** | **데이터 정의 (개발팀 협업)** | 데이터 정의서 (초안) |
| **Phase 4** | 흐름 및 화면 설계 | 유스케이스, 화면 설계서 |
| **Phase 5** | 예외 처리 및 최종 명세 | 예외 케이스 목록, 입출력 정의서 |

---

## 1. Phase 1: 요구사항 및 범위 확정 (Foundation)
**"무엇을, 왜, 어디까지 만들 것인가?"**

- **요구사항 정의서 작성 항목:**
    - **기능 목적:** 비즈니스적 가치와 해결하려는 문제 정의
    - **사용 주체:** 기능을 사용하는 페르소나 또는 시스템 권한
    - **포함 범위(Scope In):** 이번 스프린트/프로젝트에서 구현할 핵심 기능
    - **제외 범위(Scope Out):** 기획 범위에서 의도적으로 제외된 항목 (매우 중요)
    - **시작/종료 조건:** 기능이 트리거되는 시점과 최종적으로 도달해야 하는 상태

---

## 2. Phase 2: 정책 및 상태 설계 (Core Logic)
**"시스템은 어떤 규칙으로 움직이고, 정보는 어떻게 변하는가?"**

- **업무 규칙서 (Business Rules):**
    - 계산 로직, 승인 조건, 데이터 노출 제약 등 비즈니스 판단 기준
- **상태 정의서 (Status & Transition):**
    - 시스템 내에서 가질 수 있는 모든 상태 목록
    - **상태 전이(State Transition):** A 상태에서 B 상태로 변하기 위한 트리거(이벤트) 정의

---

## 3. Phase 3: 데이터 정의 (Data Definition - 협업)
**"어떤 데이터가 생성되고, 어떻게 변화하는가?"**
이 단계는 개발팀과 공동 작업합니다.

- **기획팀 준비 사항:**
    - 화면에 필요한 정보 항목(UI Field) 리스트업
    - 데이터 간의 비즈니스적 연관 관계 설명
- **공동 정의 항목 (개발팀 요구사항 포함):**
    - **데이터 의미:** 각 항목이 비즈니스적으로 무엇을 뜻하는지 정의
    - **CRUD 규칙:** 데이터가 생성(C), 조회(R), 수정(U), 삭제(D)되는 시점과 주체
    - **관리 기준:** 데이터 보존 기간, 논리/물리 삭제 여부 등

---

## 4. Phase 4: 흐름 및 화면 설계 (Flow & UI)
**"사용자는 어떤 경로로 이동하며 어떤 화면을 보는가?"**

- **유스케이스 및 시나리오:**
    - [입력 ➔ 검증 ➔ 처리 ➔ 데이터 변화 ➔ 결과]의 완결된 흐름
    - 데이터가 없는 흐름은 기획으로 인정하지 않음 (Phase 3 결과 반영)
- **화면 설계서 (Wireframes):**
    - 화면별 UI 컴포넌트, 입력값(필수/선택), 버튼 액션
    - 화면 간 이동 경로 및 인터랙션 정의

---

## 5. Phase 5: 예외 처리 및 최종 명세 (Edge Cases)
**"비정상적인 상황에서 시스템은 어떻게 반응해야 하는가?"**

- **예외 케이스 목록:**
    - 입력 오류, 권한 부족, 중복 요청, 시스템 처리 실패 시의 대응
    - 각 상황별 안내 메시지 및 후속 처리 로직
- **입출력 요구사항 정의서:**
    - 개발자가 API 및 DB 연동 시 참고할 최종 데이터 스펙 요약

---

## 🛠️ 개발 착수 전 필수 체크리스트 (완료 기준)

기획팀은 개발 착수 전 다음 항목이 모두 포함되었는지 최종 점검해야 합니다.

1. [ ] **완결성:** 시작과 종료 조건이 명확한가?
2. [ ] **데이터:** 모든 화면 항목의 데이터 출처와 생성/변경 규칙이 정의되었는가?
3. [ ] **상태:** 모든 상태와 상태 간 전이 조건이 누락 없이 정의되었는가?
4. [ ] **예외:** 사용자의 실수나 시스템 오류 상황에 대한 방어 로직이 있는가?
5. [ ] **합의:** Phase 3(데이터 정의) 과정에서 개발팀의 검토를 거쳤는가?
