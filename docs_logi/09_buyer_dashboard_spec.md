# 09. 구매 담당자 전용 입출고 수기 터미널 (Buyer's Manual Tracker Dashboard)

> **화면 ID**: `SCR-PUR-001`  
> **목적**: 물류 전담팀이나 바코드 시스템이 없는 환경에서, 구매 담당자가 자신이 발주한 건들의 수급 현황을 **엑셀처럼 직접 수기 기입(Inline Edit)**하여 시스템 원장에 자동 기록되게 하는 터미널.  
> **관련 사용자**: 구매(수급) 담당자

---

## 1. 해결 과제 및 핵심 정책

### 1) 수기 관리 (엑셀 방식) 및 데이터 무결성 보장
- **변경 정책**: 기존의 조회 전용 화면을 탈피하여, 사용자가 그리드 상에서 직접 [입고수량, 출고수량, 예정일, 비고]를 입력(Inline Edit)할 수 있게 함.
- **데이터 무결성 확보 (Background Mapping)**: 화면에 숫자를 적는 행위는 단순한 텍스트 저장이 아니라, 백엔드에서 **재고 원장(`inventory_operations`, `inventory_units`)** 레코드를 자동으로 생성/조정하는 트리거가 됨. (Auto-Save 메커니즘 적용)

### 2) ★ 입고 수량(Inbound Qty) 입력 편의성 로직 (Critical)
- **Default 스마트 설정**: 수급 담당자의 수기 입력 피로도를 대폭 낮추기 위해, 화면 로드 시 **[입고 수량] 필드에는 해당 발주(PO)의 [매입 수량(pol_qty)]이 기본값(Default)으로 미리 채워져 노출**됨.
- **수정 및 확정**: 사용자는 실제 입고된 수량이 100% 매입 수량과 일치하면 손댈 필요 없이 [저장]만 누르면 됨. 만약 파손이나 누락(Shortage)으로 실제 들어온 수량이 다를 경우에만 해당 숫자를 직접 깎아서(수정해서) 저장함.
- **원장 반영**: 수정 유무와 관계없이, 사용자가 입력 필드에서 포커스를 벗어나거나(Blur) 엔터를 치는 순간 확정된 그 수량을 바탕으로 최종 입고 실적이 기록되며 `io_type=RECEIPT` 원장 데이터가 생성됨. (실시간 Auto-Save)

### 3) 출고 수량 배정 및 N:M 매핑 해결
- 복수 공고용(N:M) 일괄 발주 건에서 출고가 일어날 경우, 단순한 총량 기입만으로는 어느 프로젝트(공고)에 물건이 투입되는지 알 수 없음.
- **해결 UX**: 출고 수량 셀을 클릭하거나 수량을 입력할 때, 해당 품목이 배분(할당, `po_allocations`)된 공고 목록을 보여주는 **[출고 배정 팝오버/모달]**이 나타남. 사용자는 어느 공고로 몇 개를 출고하는지 직접 분할 기입하여 저장을 완료함. 수기 입력 피로도를 덜기 위해 **'잔여 할당량 일괄 배정'** 버튼을 제공.

## 2. 화면 UI 구성 (Ant Design 5.x)

### 2.1. 상단: GNB, 역할 전환 및 지표 영역
- **GNB (8개 메뉴)**: Home, 공고 정보, 거래처 정보, 품목 정보, **입출고관리(Active)**, 관심 공고, 자주 가는 사이트, 업무 현황.
- **역할 전환 스위처 (Role Switcher)**: 
  - **구매오너 (김철수)**: 모든 품목 조회 및 수정 가능.
  - **연관담당자 (이영희)**: 본인 귀속 품목만 수정 가능, 타 담당자 품목은 '병합 발주' 안내와 함께 읽기 전용 처리.
- **DEV GUIDE 모드**: ON/OFF 토글 제공. 활성화 시 UI 요소별 정책 설명 메모(Sticky Note) 노출 및 실시간 수정 가능.
- **수급 요약 정보**: 
  - (미입고 지연 품목, 오늘 입고 예정, 이번 주 출고 예정) 3대 핵심 지표 카드 상단 고정.
- **액션 버튼**: 
  - **[엑셀 다운로드]**: SheetJS를 활용하여 현재 뷰의 데이터를 엑셀로 추출.
- **Auto-Save**: 수동 저장 버튼을 없애고, 입력 즉시 서버와 동기화되는 현대적 터미널 UX 구현.

### 2.2. 좌측 사이드바 (LNB): 진행중인 프로젝트 리스트
- **역할**: 한 명의 구매 담당자가 동시에 진행하는 약 20여 개의 프로젝트(공고) 목록을 리스트업.
- **주요 기능**: 
  - **사이드바 접기/펼치기**: 납품정보의 많은 컬럼을 쾌적하게 보기 위해 좌측 LNB 닫기 가능.
  - 검색 및 필터링 기능 제공 (프로젝트명 반응형 검색).
  - 수배전반 등 품목수가 100개가 넘어가는 거대 공고도 스크롤링과 함께 부드럽게 렌더링하도록 지원.
  - 특정 프로젝트 클릭 시 우측 메인 그리드 영역의 데이터가 해당 프로젝트에 귀속된 발주서(PO) 및 세부 품목 트림으로 전환됨.
  - 리스트 항목에 **입고 진행률(Blue)** 및 **출고 진행률(Green)** 듀얼 수치 표시. (발주서 뷰에서는 입고율만 표시)

### 2.3. 중앙 메인: 수급/입출고 계층형 입력 그리드 (Tree Data Grid - Editable)
- **컴포넌트**: `Table` 컴포넌트 (`expandable` 지원), 내부에 `InputNumber`, `DatePicker`, `Input` 컴포넌트를 사용한 Inline Edit.
- **계층 (Hierarchy)**: `[+] 프로젝트/공고 (Project) -> [+] 발주서/거래처 (PO/Vendor) -> [-] 세부 납품품목 (Item)`

- **주요 컬럼 구성 (13개 Columns)**:
  1. **NO**: 행 번호 (Project-PO-Item 계층 인덱스)
  2. **품목 정보 (ITEM / PO)**: 품목명 및 발주번호 노출. 담당자별 마커(Blue/Purple) 표시.
  3. **모델명/규격**: 모델 사양
  4. **거래처명**: Vendor 이름
  5. **납품조건**: 도착도(DDP) 등
  6. **내 물량**: 로그인 유저에게 할당된 수량
  7. **입고/전체** ✏️ (Inline Edit):
      - **Default**: 매입 수량 100% 세팅.
      - **과입고(Over-delivery)**: 발주량 초과 입고 시 **Indigo 컬러 하이라이트** 및 'OVER' 배지 표시.
  8. **입고예정일**: 예상 도착일
  9. **입고일자** ✏️: 실제 입고 확인일 (캘린더 선택기)
  10. **출고실행** ✏️: (Project View 전용) 현장 출고 수량. 입고 수량 한도 내 입력 가능.
  11. **출고일자** ✏️: (Project View 전용) 실제 출고일
  12. **계약납기일**: 계약상 준수 기한
  13. **비고** ✏️: 최대 100자 수기 메모.

### 2.4. 인라인 출고 배정 (Inline Outbound Allocation)
- **목적**: 엑셀 방식의 직관적인 공고(프로젝트) 단위 할당.
- **디자인/내용**:
  - 최상위 레벨이 '프로젝트'로 묶여 있으므로, 깊이(Level 3)에 있는 품목 행에 출고 수량을 적는 즉시 해당 공고로 직접 출고 배정이 확정됨.
  - 별도의 N:M 팝오버(모달창)를 띄우는 번거로운 과정을 없애 업무 속도를 대폭 단축.
  - **★ 데이터 정합성 검사**: 인라인 출고 수기 입력 시, 입력된 '출고 배정 수량'은 해당 행의 '확정된 입고 수량'을 초과할 수 없도록 실시간 제어 및 알림 제공.

## 3. 화면 입력값 백엔드 맵핑 (Data Integrity Logic)

화면 단은 단순 엑셀처럼 보이나, 물류 전산 원장의 정합성(4축 모델)을 백그라운드에서 100% 준수합니다.

1. **[입고수량] 확정 시 동작 (RECEIPT)**:
   - 사용자가 Default로 채워진 `15(매입수량)`을 그대로 [저장]할 경우:
   - → 시스템 트리거: `inventory_units` 15개(혹은 그룹 1건) 생성 (`iu_pol_sn` 매핑).
   - → 시스템 트리거: `inventory_operations` (`io_type=RECEIPT`) 생성 + `goods.g_stock` 15 증가.
2. **[수량 감소/수정 로직] 감소 시 예외 처리 (ADJUSTMENT)**:
   - 만약 일부 파손으로 인해 Default 값 `15`를 `10`으로 깎아서(감소) 수정한 뒤 저장할 경우 (또는 과거 기록에서 -5 만큼 다시 내릴 경우):
   - → 시스템 트리거: 부족분만큼 최초 `RECEIPT`를 남기고, 이후 단계에서 조기 반영 수정을 해야될 시 과거 원장 Delete 대신 `inventory_operations`에 새로운 `io_type=ADJUSTMENT` 트랜잭션을 생성하여 `iol_direction=OUT` 레코드로 재고를 5 차감함. (추적 가능한 무결성 유지)
3. **[출고수량/배정] 기입 시 동작 (ISSUE)**:
   - 팝오버를 통해 특정 공고로 잔량을 배정(+5) 후 저장할 때:
   - → 시스템 트리거: 기존 `ACTIVE` 상태의 `inventory_units` 5개를 확보하여 상태를 `DELIVERED`로 전환.
   - → 시스템 트리거: `inventory_operations` (`io_type=ISSUE`) 생성 후 `goods.g_stock` 감소. `deliveries`에 연결하여 프로젝트 귀속.
4. **[예정일] 업데이트**:
   - 텍스트/날짜 수정 시 `purchase_orders.po_expected_delivery_at` 최신화.
5. **[Auto-Save] 시 동작**:
   - 사용자 입력 편의를 위해 중간 저장 없이 즉시 서버 동기화. 하단 토스트 팝업으로 성공 알림 제공.
